## ADR-001 1차 플랫폼: Windows PC 프로그램 (Python + PyQt6)

- **배경**: 요구사항은 PC와 모바일을 모두 언급한다. 두 플랫폼을 동시에 만들면 같은 기능을 두 번 구현해야 한다.
- **대안**
  - A. Python + PyQt6 (Windows 데스크톱)
  - B. Kotlin + Android (모바일)
- **결정**: A안. 1차 구현은 PyQt6으로 Windows PC 프로그램을 만든다. Android(Kotlin)는 M6 확장 후보로 둔다.
- **결정 근거**
  - 개발 환경이 Windows이므로 실행과 테스트가 바로 가능하다.
  - Python은 CSV, JSON 처리 연습에 적합하다.
  - PyQt6은 Qt 6 기반이며 PyQt5보다 최신이다. 신규 프로젝트에서는 PyQt6을 쓰는 것이 자연스럽다.
- **제약**: 모바일에서는 실행할 수 없다. CSV 형식을 동일하게 유지하면 나중에 Android 버전과 데이터를 공유할 수 있다.
- **관련 요구사항**: 전체 (플랫폼 기준)

## ADR-002 단어장과 학습 이력 저장 형식: CSV

- **배경**: 단어장을 불러오고 저장해야 하며, 암기와 시험 이력을 누적 저장하고 보고서를 만들어야 한다. 학습자가 엑셀로 직접 열어 볼 수 있어야 한다.
- **대안**
  - A. CSV
  - B. SQLite 데이터베이스
  - C. JSON
- **결정**: A안. 단어장(`voca_2000.csv`)과 이력(`study_history.csv`)을 CSV로 저장한다.
- **결정 근거**
  - 엑셀로 열어 확인할 수 있어 학습 초보자가 데이터를 이해하기 쉽다.
  - 이력은 행 단위 추가(append)만 하므로 DB의 기능이 필요 없다.
  - 파이썬 표준 라이브러리 `csv`만으로 처리할 수 있어 설치 항목이 늘지 않는다.
- **제약**: 이력이 아주 많아지면(수십만 행 이상) 조회가 느려질 수 있다. 1인 학습 기록 규모에서는 문제가 되지 않는다고 판단한다.
- **관련 요구사항**: REQ-001, REQ-002, REQ-010, REQ-011

## ADR-003 설정과 진도 저장 형식: JSON

- **배경**: 설정 값(하루 단어 수, 복습 비율, 기본 문제 수)과 진도(현재 일차, 마지막 학습일)는 키와 값의 묶음이다.
- **대안**
  - A. JSON
  - B. INI 설정 파일
  - C. CSV
- **결정**: A안. `data/settings.json`과 `data/progress.json`을 사용한다.
- **결정 근거**
  - 숫자, 실수, 문자열을 타입 그대로 저장할 수 있다.
  - 파이썬 표준 라이브러리 `json`으로 처리할 수 있다.
  - 중첩 구조가 필요해질 때 확장이 쉽다.
- **관련 요구사항**: REQ-005, REQ-006 (설정 범위는 명세서 5절)

## ADR-004 복습 비율 기본값

- **배경**: 기획서는 전날 복습과 오답 복습 비율을 10~30% 범위로 제안했다. 구체적인 기본값이 필요하다.
- **결정**: 전날 복습 20%, 오답 복습 10%. 설정에서 0~50% 범위로 변경할 수 있다.
- **결정 근거**: 학습 세트 대부분(70%)을 신규 단어로 두어 새 단어 학습을 우선하고, 복습은 보조로 둔다. 사용자가 승인한 값이다.
- **관련 요구사항**: REQ-006

## ADR-005 뜻이 같은 단어 처리: 출제 규칙으로 해결 (A안)

- **배경**: 단어장 2,000개 중 한글 뜻이 완전히 같거나 일부 겹치는 단어가 많다 (예: `shop`/`store` 모두 "가게"). 그대로 두면 4지선다 오답 보기가 정답과 같은 뜻이 되고, 단답형 한→영 정답 판정이 하나의 영단어만 인정하게 된다.
- **대안**
  - A. CSV 뜻은 그대로 두고, 출제 규칙으로 처리 (뜻 겹침 규칙)
  - B. 뜻이 겹치지 않도록 CSV의 뜻을 수정 (약 150개 항목)
- **결정**: A안. 4지선다 오답과 OX의 X 뜻은 뜻이 겹치는 단어를 제외하고, 단답형 한→영에서는 뜻이 겹치는 영단어를 모두 정답으로 허용한다.
- **결정 근거**
  - 데이터 원본을 바꾸지 않아 검토가 끝난 CSV를 유지할 수 있다.
  - 뜻의 세밀한 차이를 살릴 수 있다 (예: `shop`과 `store`는 실제 쓰임이 다르다).
  - 규칙은 한 곳(출제 로직)에만 두면 되므로 구현이 단순하다.
- **제약**: 뜻 토큰 비교는 문자열 기준이므로 표기가 조금만 달라도(예: "가게"와 "상점") 겹치지 않는다고 판단한다. 필요하면 나중에 동의어 목록을 따로 만든다.
- **관련 요구사항**: REQ-009

## ADR-006 단어장에서 기능어 제외

- **배경**: 초기 CSV에는 대명사(I, you, it 등), 전치사(in, at 등), 접속사(and, but 등), 한정사(some, many 등)가 포함되어 있었다. 이들은 뜻이 단순하고 문장 연결에 쓰이는 말이라 단어 암기 목적에 맞지 않는다.
- **결정**: 대명사, 전치사, 접속사, 한정사(many, much, few, several, some, any, every, all, most, other, another, enough, more, less, least, no, own), 의문부사(why, how)를 제외한다. 제외 후 내용어 2,000개로 맞추기 위해 기능어가 아닌 단어 117개를 추가했다.
- **결정 근거**: 사용자 요청 (기능어 제외). 암기 효율을 위해 명사·동사·형용사·부사 중심으로 구성한다.
- **관련 요구사항**: REQ-001, 명세서 1절 단어 데이터 기준

## ADR-007 테스트 프레임워크: unittest 사용, pytest 보류

- **배경**: 구현 단계에서 자동 테스트(채점, 일차 계산, 가중치 추첨, 이력 집계)를 작성해야 한다. 표준 라이브러리 `unittest`와 외부 도구 `pytest` 중 하나를 고른다.
- **대안**
  - A. `unittest` (표준 라이브러리)
  - B. `pytest` (외부 설치 필요)
- **결정**: A안. `unittest`로 테스트를 작성한다. `pytest`는 도입하지 않는다.
- **결정 근거**
  - ADR-002, ADR-003과 같은 원칙으로 표준 라이브러리만 쓰면 설치 항목이 늘지 않는다. 환경 변경을 줄일 수 있다.
  - 1인 개발 규모의 테스트에는 `unittest`로 충분하다.
- **제약**: `pytest`의 기능(예: 픽스처 간결성)이 필요해지면 새 ADR로 재검토한다.
- **관련 요구사항**: 전체 (테스트 방침, 아키텍처 설계서 2절)

## ADR-008 전날 복습 단어는 저장하지 않고 계산한다

- **배경**: 전날 복습 단어(REQ-006)를 매번 저장해 두면 설정(하루 단어 수)이나 단어장이 바뀔 때 저장값과 실제 계산값이 어긋날 수 있다.
- **대안**
  - A. 전날 복습 목록을 진도 파일에 저장한다.
  - B. 저장하지 않고, 직전 일차의 범위를 `words_per_day`와 단어장 순서로 매번 계산한다.
- **결정**: B안. 직전 일차는 `(일차 - 1)`로 계산하고, 그 일차의 신규 단어 범위와 암기 이력으로 복습 대상을 구한다 (프로세스 설계서 3.2절).
- **결정 근거**
  - 저장 값이 없으므로 설정이나 단어장이 바뀌어도 불일치가 생기지 않는다.
  - 저장 파일이 줄어 데이터 설계가 단순해진다.
- **제약**: `words_per_day`를 바꾸면 전날 복습 범위도 바뀐다. 저장 전 "일차 구성이 바뀝니다"를 한 번 묻는다 (UI 설계서 7절).
- **관련 요구사항**: REQ-006, 데이터 설계서 9절, 프로세스 설계서 3.2절

## ADR-009 기능어 제외 기준의 해석: 접속 부사와 on·about은 유지

- **배경**: 단어장 검토 중 접속 부사 7개(however, therefore, moreover, otherwise, besides, accordingly, instead)와 on, about이 ADR-006 제외 목록에 없어 유지되고 있었다. ADR-006은 "접속사"와 "전치사"를 제외 대상으로 명시한다.
- **대안**
  - A. 접속 부사와 on, about을 제외하고 대체 단어 13개를 채운다.
  - B. ADR-006을 문자 그대로 해석해 목록에 없는 항목은 유지하고, 해석을 명확히 적는다.
- **결정**: B안. 접속 부사는 ADR-006의 "접속사"에 해당하지 않으므로 제외 대상이 아니다. on, about은 2026-10-28 사용자 결정에 따라 유지한다. 단어장 데이터는 변경하지 않는다.
- **결정 근거**
  - 대체 단어를 채우면 승인된 단어장의 일차 번호가 전부 밀리고, 1,883개 검토 결과와 진도 기준이 함께 흔들린다.
  - 2026-10-28 사용자 결정을 뒤집지 않는다.
- **제약**: ADR-006의 제외 목록을 넓히려면 새 ADR로 결정하고, 그때 단어장과 일차 구성을 함께 조정한다.
- **관련 요구사항**: REQ-001, ADR-006

## ADR-010 외부 사전 자료는 라이선스가 명확한 개방형 자료만 쓴다

- **배경**: 단어장 뜻의 정확성을 확인하려면 사전과 대조해야 한다. 사용자가 보유한 사전이 없었다. 상용 사전은 재배포와 자동 조회가 제한되고, 일부 사전 사이트는 자동 수집을 약관으로 금지한다.
- **대안**
  - A. 상용 사전을 구매해 수작업으로 대조한다.
  - B. 사전 웹페이지를 자동으로 수집해 대조한다.
  - C. 라이선스가 명확한 개방형 자료를 쓴다. 영어 Wiktionary 추출본(kaikki.org)과 한국어 위키낱말사전 공개 API를 쓴다. 둘 다 CC BY-SA 4.0이다.
- **결정**: C안. 원본 3.4GB는 저장하지 않고, 단어장 항목에 해당하는 추출 결과와 조회 원문만 `ai-agent/claude/261118_사전대조/data/`에 둔다. 출처와 라이선스를 표기한다.
- **결정 근거**
  - 재사용 조건(출처 표기, 동일 조건 공유)이 명확하다.
  - 자동 수집 금지 약관을 피한다.
  - 대조 결과는 사람이 판정한 뒤에만 단어장에 반영한다 (자동 수정 금지).
- **제약**
  - 추출 결과와 원문은 CC BY-SA 자료의 파생물이다. 저장소를 공개할 때 같은 조건을 따라야 한다. 저장소 라이선스는 아직 정하지 않았다.
  - 공개 API를 대량으로 호출할 때는 요청 간격을 두고, 429 응답이 오면 대기 후 재시도한다.
  - 자료의 뜻 풀이는 검토 보조 수단이다. 사전 근거가 약한 항목은 "사전 미확인"으로 따로 표기한다.
- **관련 요구사항**: REQ-001 (단어 데이터 정확성), 이슈 #7

## ADR-011 단어장을 바꾸거나 설정을 바꿔도 진도와 이력은 유지한다

- **배경**: 단어장 불러오기(REQ-002)와 설정 변경(REQ-005)이 추가되었다. 진도 파일(`progress.json`)은 일차 번호만 가지고, 이력(`study_history.csv`)은 영단어 키로 단어를 가리킨다. 단어장이나 설정이 바뀌면 같은 일차 번호가 다른 단어를 가리킬 수 있다.
- **대안**
  - A. 단어장을 바꾸면 진도를 1일차로 초기화한다.
  - B. 진도와 이력을 그대로 두고, 바뀐 일차 구성을 사용자에게 알린다.
  - C. 진행 중 학습이 있으면 단어장 교체와 설정 변경을 막는다.
- **결정**: B안을 기본으로 하고, C안은 설정 변경에만 적용한다.
  - 단어장 교체와 설정 변경은 진도와 이력을 지우지 않는다.
  - 하루 단어 수를 바꾸면 저장 전에 "일차 구성이 바뀝니다"를 묻는다 (UI 설계서 7장).
  - 암기나 시험이 진행 중이면 설정을 열지 않는다. 단어장 화면으로 나갈 때는 진행 중 확인을 받는다. 나가면 진행 세션은 사라진다.
- **결정 근거**
  - 학습 기록을 지우면 복구할 수 없다 (파괴적 작업).
  - 이력이 영단어 키를 쓰므로 단어장을 바꿔도 이력의 의미는 유지된다.
  - 진행 중 세션에서는 설정을 바꿀 수 없으므로, 세션 도중 단어 목록이나 일차 구성이 바뀌는 상황을 피한다.
- **제약**
  - 단어장을 바꾸면 같은 일차 번호가 다른 단어를 가리킬 수 있다. 현재 구현은 단어장 교체 시 별도 확인을 묻지 않는다. 개선 후보로 기록한다.
  - 저장 시 번호가 1부터 다시 매겨지므로 단어장 파일의 번호는 달라질 수 있다 (데이터 설계서 9절).
- **관련 요구사항**: REQ-002, REQ-005, REQ-006

## ADR-012 웹 버전 추가: Flask 로컬 서버 (데스크톱 유지)

- **배경**: 2026-11-18 사용자가 지금까지 만든 기능을 웹에서도 작동하게 해 달라고 요청했다. ADR-001은 1차 플랫폼을 Windows 데스크톱으로 정했으므로, 웹은 데스크톱을 대체하지 않고 추가한다.
- **대안**
  - A. Flask 백엔드 + HTML 템플릿 (기존 `services/`, `storage/` 재사용)
  - B. React로 전체 재작성 (규칙 로직을 JavaScript로 다시 구현해야 하므로 두 벌을 관리하게 됨)
  - C. PyScript·Pyodide (브라우저에서 Python 실행. 초기 로딩이 무겁고 파일 접근에 제약이 큼)
- **결정**: A안. 개인 PC의 로컬 서버(`127.0.0.1:5000`)에서 실행한다. 데스크톱 버전은 그대로 유지한다.
- **결정 근거**
  - 일차 계산, 복습 구성, 출제, 채점, 보고서 로직을 한 벌로 유지한다. 데스크톱과 웹의 결과가 달라질 위험이 없다.
  - 개인 학습 이력(`data/`)이 외부 서비스로 나가지 않는다.
  - 추가 설치 항목은 Flask 하나다 (2026-11-25 사용자 승인).
- **제약**
  - 공개 배포는 대상이 아니다. 계정, 호스팅, 이력 보호 설계가 필요하므로 별도 ADR로 결정한다.
  - 주소는 `127.0.0.1`로 고정하고 디버그 모드를 끈다.
  - 암기·시험 진행 세션은 서버 메모리에 둔다. 서버를 끄면 진행 중 세션은 사라지지만 진도와 이력 파일은 남는다.
  - 데스크톱과 웹은 같은 `data/` 파일을 쓴다. 두 버전을 동시에 실행하지 않는다 (진도·이력 쓰기가 겹칠 수 있음).
- **관련 요구사항**: 전체 (REQ-001~011의 웹 화면), ADR-001, ADR-002, ADR-003

## ADR-013 단어장 편집은 메모리 초안에서 하고, 저장할 때 파일에 쓴다

- **배경**: 단어장 편집(추가, 수정, 삭제)과 웹에서의 쓰기 기능이 필요해졌다 (2026-11-25 사용자 요청). 편집 중 실수로 파일이 바뀌거나, 저장 전에 일차 구성이 바뀌는 문제를 막아야 한다. ADR-011은 단어장을 바꿔도 진도와 이력을 유지한다고만 정했다.
- **대안**
  - A. 편집 즉시 파일에 쓰기: 실수가 바로 파일에 남고, 취소할 방법이 없다.
  - B. 메모리 초안에서 편집하고 "저장"으로 파일에 쓰기 (채택)
  - C. 데이터베이스로 옮겨 편집 기록 관리: 저장 형식을 바꾸는 큰 변경이라 ADR-002와 충돌한다.
- **결정**: B안.
  1. 편집은 메모리 초안에서 한다. 파일은 "저장"을 눌러야 바뀐다. 취소하면 파일 내용으로 되돌린다.
  2. 저장할 때 기존 파일을 `<원본>.bak`으로 복사해 둔 뒤 원자적으로 교체한다 (`save_words_with_backup`). 백업은 직전 저장 한 번분만 남는다.
  3. 저장 전 확인이 필요한 경우를 정한다.
     - 단어 순서나 개수가 바뀌면 일차 구성이 달라진다 (키 순서 비교). 진도는 그대로 둔다.
     - 건너뛴 행이 있으면 저장 시 파일에서 사라진다 (백업에는 남는다).
     - 뜻이나 품사만 고친 경우는 확인 없이 저장한다.
  4. 단어장 불러오기는 초안으로만 들어간다. 저장하지 않은 변경이 있으면 버리기를 확인받는다.
  5. 진행 중인 암기·시험이 있으면 편집, 저장, 불러오기, 취소를 모두 막는다 (설정 변경과 같은 기준, ADR-011).
  6. 검증 규칙은 `services/word_editor.py` 한 곳에 둔다. 영단어 필수, 품사는 명사·동사·형용사·부사 중 하나, 뜻 한 개 이상, 영단어 중복 금지(대소문자 무시).
- **결정 근거**
  - 저장 전에는 실수가 파일에 닿지 않는다.
  - 일차 구성이 바뀌는 순간을 한 번 확인받아 사용자가 의도를 알 수 있다.
  - 데스크톱과 웹이 같은 규칙과 같은 파일 형식을 쓴다.
- **제약**
  - 초안은 메모리에만 있다. 웹 서버를 끄면 저장하지 않은 변경은 경고 없이 사라진다 (개선은 이슈 #13). 데스크톱은 창을 닫을 때 확인한다.
  - 데스크톱과 웹이 같은 파일을 동시에 편집하면 마지막에 저장한 쪽이 이긴다. ADR-012의 "동시 실행 금지"를 따른다 (개선은 이슈 #14).
  - 웹의 "CSV 불러오기"는 초안으로만 읽는다. 저장 대상은 항상 `data/voca_2000.csv`다. 데스크톱은 불러온 파일 자체에 저장한다 (기존 동작 유지).
- **관련 요구사항**: REQ-001, REQ-002, ADR-011, ADR-012
