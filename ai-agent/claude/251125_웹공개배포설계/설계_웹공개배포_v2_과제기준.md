## 3. 목표 구조

```
[브라우저] --> [학교 서버: 프록시 /2026/voca-<학번>/] --> [컨테이너 0.0.0.0:8080: gunicorn -> Flask 앱]
                                                              |
                                                       [/data/voca.db (SQLite)]
```

- 앱은 `/`를 기준으로 만든다. 접두사 `/2026/voca-<학번>/`는 프록시가 처리한다 (`SCRIPT_NAME` 또는 `ProxyFix`). 앱 코드에 학번을 쓰지 않는다.
- 컨테이너 실행 사용자는 UID 10001. `/data`(DB)와 `/tmp`만 쓴다.

### 3.1 저장소 계층 (SQLite)

서비스 계층(`services/`)은 그대로 쓰고, 저장소 계층만 바꾼다.

| 현재 파일 | 대응 테이블 | 비고 |
|----------|------------|------|
| `data/voca_2000.csv` | `words` | 번호, 영단어(키), 품사, 뜻 |
| `data/study_history.csv` | `history` | 시각, 활동, 영단어, 세션ID, 방향, 유형, 정답 |
| `data/progress.json` | `progress` | 현재 일차, 마지막 학습일 (한 행) |
| `data/settings.json` | `settings` | 설정 값 (한 행, 도전 2 대응) |
| (신규) | `users` | 계정 (도전 1). 해시 저장 |

- 첫 실행 때 `CREATE TABLE IF NOT EXISTS`로 자동 생성한다 (과제 요건).
- `words`는 2,000행을 CSV에서 최초 1회 가져온다. 이후 편집은 DB가 기준이다.
- `history.user_id`를 두어 계정별 이력을 나눈다 (도전 1). 기본 기능만 할 때는 계정 1개로 고정한다.
- 초안 보관(`.draft`)과 잠금 파일(`.smartvoca.lock`)은 DB 전환 후 필요 없다. DB 트랜잭션과 SQLite 잠금으로 대체한다 (#13, #14 설계의 웹 쪽 대체).

### 3.2 DB 테이블 초안

```
words(id INTEGER PK, num INTEGER UNIQUE, english TEXT UNIQUE COLLATE NOCASE,
      pos TEXT CHECK(pos IN ('명사','동사','형용사','부사')), meanings TEXT)

history(id INTEGER PK, ts TEXT, activity TEXT CHECK(activity IN ('암기','시험')),
        english TEXT, session_id TEXT, direction TEXT, qtype TEXT,
        correct TEXT CHECK(correct IN ('O','X','')), user_id INTEGER REFERENCES users(id))

progress(user_id INTEGER PK REFERENCES users(id), current_day INTEGER, last_study_date TEXT)

settings(user_id INTEGER PK REFERENCES users(id), words_per_day INTEGER,
         prev_review_ratio REAL, wrong_review_ratio REAL, default_question_count INTEGER)

users(id INTEGER PK, login TEXT UNIQUE, password_hash TEXT, created_at TEXT,
      stats_public INTEGER DEFAULT 0)
```

- 기본 기능만 구현할 때는 `users`를 두지 않고 `user_id` 없이 한 사용자로 운영한다. 도전 기능을 할 때 `user_id`를 채운다. 이 선택은 7절 결정 사항이다.

### 3.3 통계 (과제 기본 요건)

- 진도 현황: `progress`와 `words` 수로 계산 (현재 일차, 전체 일차, 암기 단어 수).
- 날짜별 정답률: `history`에서 `activity='시험'`을 날짜별로 집계.
- 자주 틀리는 단어 상위 N개: `history`에서 단어별 틀린 횟수와 출제 횟수 집계 (기존 `stats.py` 규칙 유지).
- 기존 보고서 기능은 유지한다. 웹에 추이 표와 진도 화면을 추가한다.

## 4. 배포 설계

### 4.1 Dockerfile (초안 구조)

```
FROM python:3.11-slim
RUN useradd -u 10001 -m app
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY src ./src
COPY data/voca_2000.csv /app/seed/voca_2000.csv
USER 10001
ENV DB_PATH=/data/voca.db
EXPOSE 8080
CMD ["gunicorn", "-b", "0.0.0.0:8080", "--workers", "1", "src.web.wsgi:app"]
```

- 첫 줄에 `# syntax=`를 쓰지 않는다. `RUN --mount`, `--network`, `--security`를 쓰지 않는다.
- `src.web.wsgi:app`: 새 진입점. `create_app`을 DB 설정으로 호출한다.
- `--workers 1`: SQLite 쓰기 충돌과 인메모리 세션을 피하기 위함.
- `requirements.txt`: `Flask`, `gunicorn`, (도전 시) `Werkzeug` 등 버전 고정. `PyQt6`는 웹 컨테이너에 넣지 않는다.
- `.dockerignore`: `data/`, `.git`, `ai-agent/`, `tests/`, `__pycache__`, `*.bak`, `*.draft`, `.env`, `.smartvoca.lock`.
- 이미지 크기: 슬림 베이스와 최소 의존성으로 500MB 이하를 목표로 한다.

### 4.2 점검 워크플로

- `docker-check.yml`은 과제가 제공하는 파일을 수정 없이 `.github/workflows/`에 둔다. 이 파일의 내용은 페이지에 전체가 없으므로 **제공 파일을 받아 확인해야 한다.**
- 제출 커밋에서 초록 체크가 나와야 한다.

### 4.3 환경변수

| 이름 | 용도 | 기본값 |
|------|------|--------|
| `SECRET_KEY` | 세션 서명 키 (실행 환경에서 주입) | 없으면 시작 실패 |
| `DB_PATH` | SQLite 경로 | `/data/voca.db` |
| `PORT` | 사용 포트 | 8080 |
| `WORD_SEED` | 최초 단어 CSV 경로 | `/app/seed/voca_2000.csv` |

비밀값은 코드와 이미지에 넣지 않는다. `.env.example`에는 이름만 적는다.

### 4.4 보안 (v1 설계 승계)

- 로그인 필수 (도전 1). 기본 기능만 할 때도 `SECRET_KEY`와 CSRF 토큰은 적용한다. 공개 서버이므로 기본 요건이다.
- CSRF 토큰, 보안 헤더, 업로드 크기 제한 (v1 4.3, 4.7절).
- 디버그 금지, 개발 서버 금지 (과제 요건).
- 접근 로그에 학습 내용을 남기지 않는다.

### 4.5 데이터 보존

- SQLite 파일은 `/data` 볼륨에 둔다. 컨테이너를 다시 띄워도 남는다.
- 백업: 과제 기간 동안 하루 1회 `voca.db`를 복사한다 (서버 정책 확인 필요).

## 7. 결정이 필요한 사항 (사용자, 11-26 전)

1. **1차 범위**: 기본 기능만 (권장) 또는 도전까지 포함
2. **데스크톱 저장 방식**: 파일 유지 (권장, ADR-002 예외 기록) 또는 DB 전환
3. **계정 방식**: 기본 기능 단계에서는 계정 1개 고정 (권장), 또는 처음부터 회원가입
4. **단어 CSV 형식**: 과제 제공 CSV(`영단어,뜻`, 2,000개)를 쓸지, 우리 단어장(`번호,영단어,품사,뜻`)을 쓸지. 과제 CSV를 받으면 품사 정보를 어떻게 할지 정해야 한다
5. **학번과 `SECRET_KEY` 주입 방식**: 학번 확인, 서버 환경변수 설정 방법 (과제 안내 확인 필요)
6. **파일명 규칙**: 과제 규칙 `분류_yymmdd_제목 vX.X.md`를 따를지, 프로젝트 규칙을 유지하고 과제용 사본만 바꿀지
7. **라이선스 결정 (#11)**: 11-30 전 필수
8. **요구사항 ID 체계**: VOCA-FR ID를 새로 쓸지, REQ와 병기할지

- **ADR-015 (제안) 배포 방식: 학교 서버 Docker 배포**: 과제 요건. gunicorn, 8080, 경로 접두사, UID 10001, `/data` 볼륨. ADR-012(로컬 실행)를 대체하는 범위와 대체하지 않는 범위를 결정 기록에 명시.
