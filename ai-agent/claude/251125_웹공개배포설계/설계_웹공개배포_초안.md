# 웹 공개 배포 설계 초안 (이슈 #15)

**작성일**: 2026-11-25
**상태**: 초안. 방향과 세부 결정은 사용자 승인 후 확정한다. 확정되면 결정 기록에 ADR-014로 추가한다.
**관련**: ADR-012 (웹 버전은 로컬 실행, 공개 배포는 별도 ADR), ADR-010 (외부 자료 라이선스), 이슈 #11 (저장소 라이선스)

---

## 1. 배경과 목적

- 현재 웹 버전은 `127.0.0.1`에서만 실행된다 (ADR-012). 다른 기기나 외부에서 쓰려면 배포가 필요하다.
- 현재 구조는 1인용 파일 저장 방식이다. 로그인이 없고, 학습 이력과 진도는 서버의 `data/` 파일에 평문으로 저장된다.
- 따라서 공개 배포는 기능 추가가 아니라 **보안과 데이터 보호 설계가 먼저**다.

## 2. 현재 상태에서 공개하면 생기는 문제 (코드 기준)

| 항목 | 현재 상태 | 공개 시 위험 |
|------|----------|-------------|
| 로그인 | 없음 | 누구나 학습 이력, 진도, 보고서를 보고 바꾼다 |
| CSRF 보호 | 폼에 토큰 없음 | 다른 사이트가 로그인한 사용자의 요청을 대신 보낼 수 있다 |
| 시크릿 키 | 실행할 때마다 무작위 생성 | 재시작 때 세션이 깨짐. 고정 키가 없어 세션 보호가 불안정 |
| 서버 실행 | Flask 개발 서버 | 운영용이 아님 |
| 데이터 저장 | `data/`의 JSON, CSV 평문 | 서버 침해 시 개인 학습 기록이 그대로 노출 |
| 실행 잠금 | `data/.smartvoca.lock` (단일 PC 기준) | 여러 인스턴스가 같은 파일을 쓰면 덮어쓰기 발생 |
| 업로드 | CSV 불러오기 (크기 제한 없음) | 큰 파일로 메모리와 디스크를 소모할 수 있다 |
| 보안 헤더 | 없음 | HTTPS 강제, 클릭재킹 방지 등이 없다 |

## 3. 선택지 비교

| 안 | 내용 | 장점 | 단점 | 판단 |
|----|------|------|------|------|
| A | 로컬 실행 유지 (현재) | 비용 없음, 데이터가 PC 밖으로 나가지 않음 | 외부 접근 불가 | **현 단계 권장** |
| B | 개인 PC를 터널로 임시 공개 (ngrok, cloudflared 등) | 설정이 빠르다 | PC가 켜져 있어야 함, 인증 없으면 누구나 접근, 데이터가 개인 PC에 그대로 있음 | 비추천 |
| C | 단일 사용자 클라우드 배포 (PaaS 또는 소형 VPS) + 로그인 + HTTPS + 영속 볼륨 | 기기와 장소에 상관없이 사용 가능. 데이터는 서버 한 곳 | 로그인, CSRF, 키 관리, 백업, 서버 비용과 운영 책임이 생긴다 | **공개가 필요하면 권장** |
| D | 다중 사용자 서비스 (회원가입, 사용자별 데이터, DB 전환) | 여러 사람이 사용 가능 | 저장소 계층 교체(ADR-002 변경), 권한 모델, 개인정보 처리방침, 약관, 이메일 인증. 규모가 크다 | 현재 범위 밖. 별도 프로젝트로 다룬다 |

**권장: 현 단계는 A 유지. 공개가 필요해지면 C로 진행한다.** D는 목적이 여러 사용자 서비스일 때만 검토한다.

## 4. C안 세부 설계 (승인 시 적용)

### 4.1 인증

- 단일 계정. 사용자 이름과 비밀번호 해시를 환경변수 또는 `.env`에 둔다 (CLAUDE.md 규칙 5, `.env`는 커밋하지 않음).
- 비밀번호 해시: `werkzeug.security.generate_password_hash` 사용 (Flask 기본 의존성, 추가 설치 없음).
- 로그인 실패를 기록하고, 일정 횟수 이상 실패하면 잠시 막는다 (요청 빈도 제한).
- 모든 화면은 로그인 후에만 접근한다. 로그인 페이지 외 라우트는 기본 거부한다.
- 로그아웃 기능을 둔다.

### 4.2 세션과 쿠키

- 시크릿 키는 환경변수 `SECRET_KEY`에서 읽는다. 코드에 쓰지 않는다. 재시작해도 세션이 유지되도록 고정한다.
- 세션 쿠키: `Secure`, `HttpOnly`, `SameSite=Lax`.
- 세션 만료 시간을 둔다 (예: 12시간).

### 4.3 CSRF

- 모든 POST 요청에 CSRF 토큰을 요구한다. 폼 템플릿에 숨은 토큰 필드를 넣는다.
- 구현 방식: `Flask-WTF` 추가(설치 승인 필요) 또는 직접 토큰 구현 중 선택. 기본 권장은 `Flask-WTF`.

### 4.4 서버 실행

- 운영 서버는 `waitress`(Windows 호환) 또는 `gunicorn`(Linux)을 쓴다. 설치 승인 필요.
- 주소와 포트는 환경변수 `HOST`, `PORT`에서 읽는다. 플랫폼이 정한 포트를 쓴다.
- `debug`는 항상 끈다.
- 업로드 크기 제한: `MAX_CONTENT_LENGTH`를 설정한다 (예: 1 MB).

### 4.5 데이터 저장

- 데이터 폴더는 환경변수 `DATA_DIR`로 지정한다 (`src/paths.py` 수정). 영속 볼륨 경로를 가리킨다.
- 파일 저장 방식은 유지한다 (ADR-002, ADR-003). 단일 인스턴스 운영을 전제로 한다.
- 단일 인스턴스 보장: 배포 플랫폼에서 인스턴스를 1개로 고정한다. 실행 잠금(`InstanceLock`)은 PID 기반이라 컨테이너 재시작 시 오판할 수 있으므로, 배포 환경에서는 잠금 대신 인스턴스 수 1을 설정으로 보장한다 (설계 검토 필요).
- 백업: 하루 1회 `data/` 전체를 암호화 저장소에 복사한다. 보관 기간은 30일을 기본으로 한다 (승인 시 확정).

### 4.6 개인정보 보호

- 학습 이력, 진도, 설정, 보고서는 개인 데이터로 취급한다.
- 저장 볼륨 암호화를 플랫폼 기능으로 켠다.
- 접근 로그에 학습 내용(단어, 답안)을 남기지 않는다. 요청 경로와 시각, 상태 코드만 남긴다.
- "내 데이터 내려받기"와 "데이터 전체 삭제" 기능을 둔다 (단일 사용자라도 삭제 권리 보장).
- 개인정보 처리방침 문서는 불특정 다수 공개일 때만 필요하다. 단일 사용자 운영이면 생략 가능 (승인 시 확정).

### 4.7 보안 헤더와 전송

- HTTPS만 허용한다 (플랫폼 인증서 사용). HTTP 요청은 HTTPS로 넘긴다.
- 응답 헤더: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy`(인라인 스크립트 최소화).
- 템플릿 자동 이스케이프는 이미 적용되어 있다 (현재 유지).

### 4.8 의존성과 점검

- `requirements.txt`에 버전을 고정한다.
- 배포 전 `pip-audit`으로 취약점을 확인한다 (설치 승인 필요).

## 5. 코드 변경 범위 (C안 기준, 추정)

| 파일 | 변경 |
|------|------|
| `src/web/__main__.py` | 환경변수 `HOST`, `PORT`, `DATA_DIR`, `SECRET_KEY` 읽기. 운영 서버로 실행 |
| `src/web/app.py` | 로그인 라우트, 인증 요구, CSRF 토큰, 보안 헤더, 업로드 크기 제한, 고정 시크릿 키 |
| `src/web/templates/` | 로그인 화면, 로그아웃 링크, CSRF 숨은 필드 |
| `src/paths.py` | `DATA_DIR` 환경변수 우선 적용 |
| `src/storage/instance_lock.py` | 배포 환경에서는 잠금을 건너뛰는 설정 추가 (설계 검토 후) |
| 새 파일 `src/web/auth.py` | 비밀번호 확인, 로그인 실패 제한 |
| 테스트 | 인증 없이 접근 시 거부, CSRF 토큰 없으면 거부, 보안 헤더, 내려받기·삭제 기능 |
| 설정 파일 | `.env.example` (값은 없이 이름만) 추가. `.env`는 `.gitignore`에 있음 |

데스크톱 버전(`src/main.py`)과 서비스·저장소 계층(`services/`, `storage/`)은 바뀌지 않는다.

## 6. 단계 계획 (C안 승인 시)

| 단계 | 내용 | 완료 기준 |
|------|------|----------|
| 1 | 환경변수 설정, 운영 서버 실행, 고정 시크릿 키 | 로컬에서 운영 서버 모드로 기동 |
| 2 | 로그인, 로그아웃, 인증 요구, 로그인 실패 제한 | 로그인 없이 어떤 화면도 열리지 않음 (테스트) |
| 3 | CSRF 토큰, 보안 헤더, 업로드 제한 | 토큰 없는 POST 거부 (테스트) |
| 4 | 내려받기, 전체 삭제 기능 | 내려받은 파일에 학습 기록이 모두 포함 |
| 5 | 배포 플랫폼 설정, 영속 볼륨, HTTPS, 백업 | 외부 기기에서 로그인해 학습 가능 |
| 6 | 점검: 취약점 점검, 접근 로그 확인, 복구 연습 | 백업에서 복구 1회 성공 |

## 7. 결정이 필요한 사항 (사용자)

1. **방향**: A(로컬 유지), B(터널 공개, 비추천), C(단일 사용자 클라우드), D(다중 사용자 서비스) 중 선택
2. **공개 범위**: 본인만 쓸지, 지인 몇 명인지, 불특정 다수인지 (C는 본인 또는 소수에 맞춤)
3. **호스팅**: 예산과 선호 (PaaS 또는 소형 VPS). 볼륨 지원과 HTTPS 제공 여부가 선택 조건이다
4. **데이터 저장**: 파일 유지(단일 사용자, 단일 인스턴스) 또는 DB 전환 (ADR-002 변경 필요)
5. **개인정보 처리방침**: 불특정 다수 공개인 경우에만 필요
6. **라이선스 (#11)**: 공개 저장소로 할지에 따라 사전 파생 데이터 처리가 달라진다. 공개 전에 먼저 정해야 한다
7. **추가 설치 승인**: `Flask-WTF`, 운영 서버(`waitress` 또는 `gunicorn`), `pip-audit`

## ADR-014 웹 공개 배포 방식 (제안)

- **상태**: 제안. 사용자 결정 전.
- **배경**: 웹 버전을 외부에서 쓰고 싶다는 요구가 있다. 현재 구조는 로그인과 CSRF 보호가 없고, 개인 학습 데이터가 평문 파일로 저장된다 (2절).
- **대안**: A 로컬 유지, B 터널 임시 공개, C 단일 사용자 클라우드 배포, D 다중 사용자 서비스 (3절).
- **권장**: A를 현 단계로 유지하고, 공개가 필요해지면 C로 한다. D는 별도 프로젝트로 다룬다.
- **결정**: (사용자 결정 대기)
- **제약 (C 선택 시)**: 단일 인스턴스, 파일 저장 유지, HTTPS 필수, 로그인 필수, 시크릿 키 환경변수 관리, 개인 데이터 암호화 볼륨, 일일 백업.
- **관련**: ADR-002, ADR-003, ADR-010, ADR-012, 이슈 #11
