**결론**: 과제를 제출하려면 리포를 공개해야 하고, 공개하려면 라이선스와 이력 정리를 **11-30 전에** 정해야 한다. 라이선스 문제는 과제 기준으로 더 급해졌다.

## 3. 선택지 (과제 기준 재정리)

| 안 | 내용 | 공개 가능 | 이력 처리 | 비고 |
|----|------|----------|----------|------|
| A | 라이선스 없이 공개 (기본 저작권 유지) | 가능하지만 재사용 권리가 없다 | 원문 파일 처리 필요 | 재사용을 막는 것이 과제 취지와 맞지 않을 수 있음 |
| B | 코드 MIT, 단어 데이터와 사전 파생 파일은 CC BY-SA 4.0으로 명시 | 가능 | 원문 파일은 CC BY-SA 자료로 표시하고 그대로 둔다 | 파일별 라이선스 표기가 필요하다 |
| C | 코드 MIT, 원문 파일 3개를 **이력 포함 삭제** 후 공개 | 가능 | force-push 필요 (11-30 이전만) | 기존 검토 기록의 근거 원문이 사라진다 |
| D | 코드 MIT, 원문 파일은 공개 리포에서 **제외**하고 검토 결론만 남김 | 가능 | C와 같이 이력 정리 필요 | C와 같은 문제 |

**과제 기준 권장 (의견)**: **B**. 이유: (1) 이력을 고치지 않아도 된다, (2) 사전 검토 근거가 남아 ADR-010을 지킨다, (3) 파일 라이선스 표기만 추가하면 된다. 단점은 파일별 표기가 필요하다는 점이다.

코드 라이선스는 MIT를 권장한다. 과제 기준에는 조건이 없어 어떤 라이선스든 가능하다.

## 4. 사용자가 11-30 전에 정해야 할 것

1. 공개 여부: 과제 제출을 위해 **공개** (필수)
2. 라이선스 안: A, B, C, D 중 선택 (권장 B)
3. 코드 라이선스: MIT (권장) 또는 다른 것
4. 이력 처리: 원문 파일을 그대로 둘지(B), 이력 정리를 할지(C, D)
5. 결정 후 적용: `LICENSE` 파일, 데이터 파일 표기, README 표기, ADR 기록

## 5. 결정 전 할 수 있는 일 (승인 시)

- 리포 루트에 `LICENSE`(MIT) 초안을 준비하고 커밋하지 않는다.
- 사전 원문 파일 목록을 `NOTICE` 문서로 정리한다 (B안의 출처 표기 근거).
- 어떤 안을 고르든 결정 기록에 ADR을 추가한다 (`docs/` 수정 승인 필요).
